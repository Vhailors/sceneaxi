### AP-01 — High / P0: glTF graph traversal exhausts stack

- **Source:** `packages/importers/src/contained-gltf.ts:1227` `parseGltf.visit`; recursion at `:1366`.
- **Reproduction/refutation:** admitted embedded triangle, `nodes = Array.from({length:2500}, (_,i) => i===2499 ? {mesh:0} : {children:[i+1]})`, scene roots `[0]`. JSON is flat/shallow, well under 8 MiB, so the JSON-depth64 and byte budgets do not protect graph depth. Depth100 control parses; depth2,500 public stage throws. Actual `sceneaxi asset import ... --json` returns INTERNAL/exit1, not a named validation refusal.
- **Impact:** user-selected small local files can interrupt importer/desktop synchronous host work. No code execution or outside-root write claimed.
- **Owner/fix:** assets builder owns importer and package test; replace recursive DFS with bounded iterative traversal retaining cycle/multi-parent detection and deterministic order. Add explicit node/depth/operation limits and a named existing refusal, with truthful docs. Never broaden formats.
- **Acceptance:** public stage/propose and spawned CLI for deep chain, cycle, DAG duplicate parent and valid control; no RangeError, no pre-accept project/journal changes; unchanged existing digests. Run `pnpm exec vitest run packages/importers/test/contained-gltf.test.ts tests/e2e/asset-ingestion-golden.test.ts` then integration `pnpm gate`.

### AP-02 — Medium / P1: indexed triangles incorrectly require vertex count divisible by three

- **Source:** `packages/importers/src/contained-gltf.ts:1254` `parseGltf` requires `positions.length % 9 === 0` before checking indices.
- **Reproduction/refutation:** POSITION accessor count4 (square), uint16 indices `[0,1,2,0,2,3]`, triangle mode4, valid bounded embedded bytes. Public stage and CLI refuse malformed. Count3 unindexed control parses. These are indexed triangles already admitted by the profile, not a request to add quads/topology formats.
- **Impact:** routine shared-vertex meshes are rejected unless their vertex count happens to be divisible by three.
- **Owner/fix:** assets builder changes only POSITION validation versus unindexed triangle completeness; indexed completeness remains based on indices and range checking.
- **Acceptance:** 4-vertex/6-index square imports, reloads and preserves exact canonical bytes; unindexed count4, non-triplet indices, out-of-range indices still refuse. Same targeted command as AP-01, plus asset pipeline golden.

### AP-03 — Medium / P1: changed plugin bytes are scanned but cached old entrypoint is evaluated

- **Source:** `packages/plugin-host/src/pipeline.ts:430-431` `processCandidate`; `packages/plugin-host/src/host.ts:80` `load`.
- **Reproduction/refutation:** write trusted package exporting `capabilities={}`, call `host.load([root])`, rewrite same entrypoint to `capabilities={unexpected:42}`, call `load([root])` again. Result remains loaded1/refused0 despite current manifest declaring no capabilities. Import uses the same Node module URL; reopening a host in the same process does not invalidate Node's cache. Registry/version checks are real and passed; they do not bind loaded code to inspected bytes.
- **Impact:** listings/inspection may describe current package bytes while exposing stale implementations. This is a lifecycle/integrity problem in trusted code, **not** evidence of hostile-code sandbox escape.
- **Owner/fix:** plugin builder establishes immutable inspected-byte identity per process (entry and inspected dependency graph); refuse changed content with a named reason and restart guidance rather than uncontrolled cache-busting/module accumulation. Preserve exact capability/version checks and deterministic listings.
- **Acceptance:** unchanged repeated loads deterministic; changed entrypoint and transitive helper cannot expose cached old code as current; refusal before lookup with no old implementation addressable; new-process unchanged package works. `pnpm exec vitest run packages/plugin-host/test/load-refuse.test.ts packages/plugin-host/test/refuse-matrix.test.ts tests/e2e/plugin-capability-golden.test.ts`.

### AP-05 — High / P0: project-local destination symlink redirects hot reload into unrelated file

- **Reproduction/refutation:** fresh composed project; `assets/triangle.gltf` symlink to root `unrelated.gltf` containing identical initial triangle bytes. Recovery returns copiedPaths `[assets/triangle.gltf]`, **unrelated.gltf now equals new source bytes**, symlink remains. - **Impact:** review-approved asset reload can overwrite an unrelated same-root file; contradicts documented destination-symlink refusal and ownership guarantee.
- **Owner/fix:** assets builder checks the lexical destination before dereference/canonicalization, rejects regular/dangling in-root/out-of-root destination symlinks, preserves canonical containment and copy race checks. Coordinate authoring apply callers only if acceptance/recovery ordering changes.
- **Acceptance:** same fixture refuses before proposal/journal/source writes; reload/recovery never overwrites unrelated bytes; all existing valid copies/recovery remain deterministic. Add regression under `packages/importers/test/contained-gltf.test.ts`, run targeted suites plus `pnpm gate`.
