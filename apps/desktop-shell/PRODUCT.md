# Product

## Register

product

## Users

SceneAxi operators and creators use the packaged desktop application to open, author, inspect, and run interactive Game and Web Experience scenes locally. They need dense, trustworthy controls that preserve project state and make every unavailable or unsafe path explicit.

## Product Purpose

The desktop application gives the shared SceneAxi engine and authoring contracts a packaged local surface without creating a second editor implementation. Success means operators can complete supported local workflows, understand named refusals, and distinguish offline, user-funded BYOK, and separately metered hosted capabilities without ambiguity.

## Brand Personality

Precise, capable, restrained. The interface should feel like a serious creative tool: compact enough for sustained work, explicit about evidence and state, and confident without decorative spectacle.

## Anti-references

Do not resemble a generic assistant chat app, a consumer settings dashboard, a storefront, or an over-decorated AI control panel. Avoid invented visual facts, hidden fallback behavior, ambiguous availability, duplicated editor chrome, and controls that appear live when the underlying capability refuses.

## Design Principles

- Keep the shared Engine Desktop chrome authoritative; desktop integrations bind or extend it without forking its state machine.
- Make capability state and named refusals visible at the point of action.
- Preserve the product boundary between local, BYOK, and hosted work in both copy and behavior.
- Prefer compact, familiar tool controls that disappear into the authoring workflow.
- Treat runtime evidence as observed state, never as a claim inferred from counters or configuration.

## Accessibility & Inclusion

Maintain at least WCAG AA contrast for text and controls, full keyboard operation, explicit labels and status announcements, visible focus, and reduced-motion-safe state changes. Kids remains a refuse-only profile whose safety boundary is structural and independently enforced before any assistant or provider action.
